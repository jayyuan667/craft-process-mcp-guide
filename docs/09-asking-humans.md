# 09 · 向人提问的格式

适用于没有结构化提问控件的 harness（只有聊天输入框）。目标不是让人多点几下，是**让人用最少的字给出可解析的答案**。

## 四条硬规则

**默认值 + 只改例外。** 先声明「系统读数如下，默认全部采用，只回需要改的」，然后给表。用户回 `3=+0.13；7=无`，其余不写。

**一批不超过 5 项，且不混类型。** 数值确认一批、有/无判断一批、模板选择单独一批。三类答案的语法不同，混在一起必然要人自己对齐编号。

**每项带证据。** 数值项给出图上原文（不是你复述的值）；检测项给裁剪图或 bbox。没有证据的确认只是让人替你签字。

**写完回显。** `我理解为：3 改为 +0.13，7 无，其余采用，对吗？` 一次回显比事后返工便宜。

## 模板 A：数值确认

```
系统读数如下，默认全部采用，只回需要改的项（格式：编号=值）。

| # | 项目 | 系统值 | 图上原文 |
|---|------|--------|----------|
| 1 | 整体长度 | 1786 | 1786±0.3 |
| 2 | 最大外径 | Φ126 | Φ126±0.1 |
| 3 | 端部外径 | Φ72 | Φ72 +0.13/（下偏差不清） |

看不清的写「看不清」，我会留作待确认，不会猜。
```

回答示例：`3=Φ72 +0.13/-0.02；4 看不清`

## 模板 B：有/无判断

```
以下结构请各回「有 / 无 / 看不清」，一次一行也行，合并写也行：

5. 主视图左端外螺纹 —
6. B 向端面腰型键 —
7. 右端头部内键槽 —（技术要求提到槽内表面氮化）

依据：编号 5 附裁剪图 A；6、7 见 B 向视图与技术要求第 4 条。
```

回答示例：`5有 6有 7看不清`

## 模板 C：模板选择

```
候选里三个都是 complete，区别在来源图号：

| 模板 | 来源图号 | 是否本图 |
|------|----------|----------|
| T01 | 与本图相同 | 是 |
| T02 | 另一尺寸档 | 否 |
| T23 | 另一机型 | 否 |

建议 T01（槽位值和工艺文本本来属于这张图）。回复「T01」或指定其他。
```

选择类问题永远给推荐项，不要让用户在十几个编号里挑。

## 回答语法

定死几个 token，减少歧义：

`正确` / `=值`（更正）/ `无` / `有` / `看不清` / `跳过`

一条回复里可以混合，用分号或换行分隔：`3=+0.13；6无；7看不清`。

agent 必须把解析结果回显一次再写库。解析不了的部分单独列出来重问，不要默认成「正确」。

## 超过 5 项或混了类型时：换工具

人肉对齐编号的成本随项数线性上升。超过 5 项、或者同时有数值和有无判断，直接生成复核单：

```bash
python tools/review_sheet.py --workbench wb.json --image input-1.png --out sheet.html
```

打开点选、生成 JSON、复制回来。这一步把「文本框 harness」降级成「浏览器表单」，不需要对方 agent 有任何结构化提问能力。

## 不要这样问

```
请按编号确认或更正，无法辨认可答"看不清"。我只会把你确认的内容写回工作台：总长…
1776 是内侧尺寸…大端最大外径…小端外径…左端螺纹…主视图左端有外螺纹：确认有/没有？…
可回复"1正确；2正确；3…"。
```

问题不在信息不全，在于：七项挤成一段、没有分行、三种答案类型混在一起、要用户自己在脑子里建索引、回复串还要自己编号对齐。任何一项拿不准，整句重写。

## agent 自检

开口之前问自己四个问题：

这些项里有没有我自己能核实的？有就先核实，别问人。

这些项是不是都卡住了流程？不是的往后放。

每项有没有证据可给？没有就先去找，别让人凭空确认。

超过 5 项了吗？超过就生成复核单。
